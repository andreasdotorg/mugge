## F-288: disko legacy MBR table warning — GPT migration not completed

**Severity:** medium
**Status:** open
**Found in:** `nix/nixos/disko.nix`
**Affects:** nixos-rebuild, SD card image build
**Found by:** owner (session 14, deploy output)

### Description

Every `nixos-rebuild switch` and `nix build` emits this warning:

```
evaluation warning: The legacy table is outdated and should not be used.
We recommend using the gpt type instead.
```

The disko configuration uses `type = "table"` (MBR) instead of `type = "gpt"`.
F-273 addressed partition label alignment but kept MBR. The assumption was that
Pi 4 requires MBR for boot compatibility, but this needs verification — the Pi 4
firmware can boot from GPT if the partition layout is correct (FAT32 first
partition).

### Questions to resolve

1. Can the Pi 4 boot from a GPT-partitioned SD card? (Pi 4 EEPROM with
   2024+ firmware supports GPT via the FAT32 partition discovery.)
2. Does disko's GPT type work correctly for the Pi 4 SD card image builder?
3. Are there any disko features (like the test framework) that require GPT?

### Fix required

Investigate GPT feasibility for Pi 4 boot. If GPT works, migrate `disko.nix`
from `type = "table"` to `type = "gpt"`. If MBR is truly required, document
why and suppress the warning.
