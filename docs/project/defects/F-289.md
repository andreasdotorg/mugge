## F-289: /boot/firmware not mounted — firmware updates silently skipped

**Severity:** medium
**Status:** open
**Found in:** `nix/nixos/disko.nix`, NixOS activation script
**Affects:** nixos-rebuild, Pi firmware updates
**Found by:** owner (session 14, deploy output)

### Description

Every `nixos-rebuild switch` outputs:

```
Pi 4 firmware partition not mounted at /boot/firmware, skipping update.
```

The firmware partition (FAT32, first partition on the SD card) is not mounted
at runtime. The previous assumption (F-266) was that `/boot/firmware` is only
needed during initial SD card image creation and not at runtime.

This assumption is questionable:

1. **Firmware updates:** NixOS's `raspberrypi-firmware` and `uboot` packages
   may need to write updated firmware files (start4.elf, fixup4.dat,
   u-boot.bin, config.txt) to `/boot/firmware` during `nixos-rebuild switch`.
   If the partition isn't mounted, these updates are silently skipped.

2. **config.txt changes:** Pi boot configuration (`config.txt`, `cmdline.txt`)
   lives on the firmware partition. Any NixOS module that needs to modify boot
   parameters (e.g., kernel command line, GPU memory, overlays) cannot do so
   if the partition isn't mounted.

3. **Kernel updates:** On Pi 4, the kernel image may need to be placed on the
   firmware partition for U-Boot to find it (depends on boot chain config).

### Research Findings (session 16)

#### Q1: Does nixos-rebuild need to write to /boot/firmware?

**Yes.** `firmware.nix` defines an activation script (`system.activationScripts.pi4audio-firmware`)
that runs on every `nixos-rebuild switch`. It copies fresh firmware files from
the Nix store to `/boot/firmware/`:

- VideoCore blobs: `bootcode.bin`, `fixup*.dat`, `start*.elf`
- U-Boot binary: `u-boot-rpi4.bin`
- GICv2 stub: `armstub8-gic.bin`
- Device tree: `bcm2711-rpi-4-b.dtb`
- DT overlays: `disable-bt.dtbo`, `disable-sd-uhs.dtbo`
- Boot config: `config.txt`

These files are read by the VideoCore firmware and U-Boot **before Linux
starts**. They are NOT part of the NixOS store — they live on a separate
FAT32 partition.

#### Q2: What is the "skipping update" message?

It comes from `firmware.nix` line 154. The activation script attempts an
on-demand mount (`mount /dev/disk/by-label/FIRMWARE /boot/firmware`) before
copying files. If the mount fails (or the directory doesn't exist), it prints
the warning and skips all firmware file updates.

The mount options in both `configuration.nix` and `disko.nix` are
`[ "nofail" "noauto" ]`. `noauto` prevents systemd from mounting the
partition at boot. The on-demand `mount` in the activation script should
work, but it may be failing due to:

1. The activation script runs as root — permissions are not the issue
2. The `FIRMWARE` label device should be present (`/dev/disk/by-label/FIRMWARE`)
3. Most likely: the `/boot/firmware` directory exists but the mount fails
   silently (`2>/dev/null || true` in the script suppresses mount errors)

#### Q3: What is the impact of stale firmware?

**Medium severity.** The firmware files on the FAT partition have not been
updated since the SD card was first flashed. If NixOS updates any of these
packages across rebuilds, the running firmware is out of sync:

- `raspberrypifw` — VideoCore GPU firmware (`start4.elf`, `fixup4.dat`)
- `ubootRaspberryPi4_64bit` — U-Boot bootloader
- `raspberrypi-armstubs` — GICv2 interrupt controller stub

The **kernel itself is NOT affected** — it lives on the ext4 root partition
and is loaded by U-Boot via extlinux.conf. `nixos-rebuild switch` correctly
updates the kernel and extlinux configuration on `/boot/extlinux/` (which
is on the root filesystem, not the firmware partition).

**config.txt is also stale.** Any changes to `configTxtFile` in firmware.nix
(GPU memory, DT overlays, boot parameters) will not take effect until the
firmware partition is updated.

#### Q4: Boot chain analysis

```
Pi 4 boot sequence:
  1. VideoCore reads FAT partition (by MBR type 0x0C)
     -> bootcode.bin -> start4.elf -> config.txt -> armstub8-gic.bin
  2. VideoCore loads U-Boot (u-boot-rpi4.bin) from FAT partition
  3. U-Boot reads extlinux.conf from ext4 root (/boot/extlinux/)
  4. U-Boot loads kernel + initrd + DTB from ext4 root (Nix store paths)
  5. Linux boots

Steps 1-2 use /boot/firmware (FAT). Steps 3-4 use / (ext4).
nixos-rebuild switch updates steps 3-4 correctly. Steps 1-2 are stale.
```

#### Q5: Does neededForBoot help?

No. `neededForBoot` ensures the filesystem is available in the initrd (early
boot). The firmware partition is read by VideoCore/U-Boot **before the kernel
even starts** — initrd is irrelevant. What's needed is either:

1. Mount at boot (remove `noauto`) so the activation script finds it mounted, or
2. Fix the on-demand mount in the activation script (debug why it fails)

### Recommended Fix

**Option A (simplest):** Remove `noauto` from the mount options. Change
`options = [ "nofail" "noauto" ]` to `options = [ "nofail" ]` in both
`configuration.nix` (line 70) and `disko.nix` (line 54, 81). This mounts
the firmware partition at boot. The `nofail` option ensures boot continues
even if the partition is missing (e.g., during image builds).

**Option B (current design, fix the script):** Keep `noauto` but debug
why the on-demand mount in firmware.nix fails. Add logging to the mount
command (remove `2>/dev/null`) to see the actual error. The script's
`mount /dev/disk/by-label/FIRMWARE "$FWDIR" -t vfat -o nofail` should
work as root — the failure may be a missing mount point directory or a
by-label symlink timing issue during activation.

**Recommendation:** Option A. The firmware partition is small (256 MiB FAT32,
read-only in normal operation) and having it mounted is harmless. The
`noauto` was defensive but causes firmware staleness.
