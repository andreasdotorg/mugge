## F-291: PipeWire running at SCHED_OTHER instead of SCHED_FIFO/88 on NixOS image

**Severity:** High
**Status:** RESOLVED
**Resolved by:** Session 15 deployment — NoNewPrivileges fix deployed, Pi verified at SCHED_FIFO/88
**Found in:** NixOS image (PipeWire systemd unit configuration)
**Affects:** All audio operation, all stories
**Found by:** worker-2 during US-155 deployment verification (session 15)

### Description

PipeWire on the Pi (192.168.178.35, NixOS image) is running at SCHED_OTHER
(nice -11) instead of the required SCHED_FIFO/88. The systemd override has
`CPUSchedulingPolicy=fifo` and `CPUSchedulingPriority=88` but
`NoNewPrivileges=yes` on the base unit likely blocks RT promotion.

Journal shows on every PipeWire start:

```
mod.rt: could not set nice-level to -11: Permission denied
```

### Impact

RT scheduling is required for xrun-free audio under load. The system works at
low load but will fail under production conditions (DJ set, live performance).
This blocks reliable audio operation for all modes.

### Root Cause (suspected)

This is the same class of issue as F-020 (PipeWire RT self-promotion failure
on PREEMPT_RT). The workaround previously deployed (systemd user service
drop-in at `~/.config/systemd/user/pipewire.service.d/`) may not be active
on the current NixOS image build. `NoNewPrivileges=yes` on the base systemd
unit prevents the service from acquiring RT privileges even when the override
specifies `CPUSchedulingPolicy=fifo`.

### Fix required

1. Ensure the NixOS configuration sets `NoNewPrivileges=no` (or removes the
   restriction) on the PipeWire user service unit.
2. Verify the systemd drop-in override for SCHED_FIFO/88 is included in the
   NixOS image build.
3. After fix, verify with `chrt -p $(pidof pipewire)` that PipeWire runs at
   SCHED_FIFO priority 88.
4. Verify journal no longer shows `Permission denied` for RT/nice operations.

### Verification

Validated under 43-minute DJ load test (session 15):
- Pre-fix: ~3 xruns/minute at SCHED_OTHER
- Post-fix: ~0.07/minute at SCHED_FIFO/88 (3 total, likely startup transients)
- Convolver pipeline essentially zero new errors under sustained load
- PR #38 carries the permanent flake fix
