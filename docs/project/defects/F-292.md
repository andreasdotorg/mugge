## F-292: GraphManager fails to create links on startup — manual pw-link required

**Severity:** Critical
**Status:** RESOLVED
**Resolved by:** Session 15 deployment — D-065 applied on Pi (90-no-auto-link.conf removed, node.always-process=true added). Flake PR still needed for permanence.
**Found in:** WirePlumber config (`90-no-auto-link.conf`), not GraphManager
**Affects:** All audio operation, all modes, all stories. Blocks automated boot-to-audio.
**Found by:** owner (elevated from known issue; observed in GM-12 DJ session and
session 15 deployment verification)

### Description

The GraphManager reconciler fails to create the expected PipeWire link topology
on startup. When the system boots and GM enters its default mode (standby or DJ),
the reconciler does not establish any audio links. The operator must manually run
`pw-link` commands to wire the audio graph before audio flows.

This was the blocker for the GM-12 DJ session (40+ minutes, zero xruns — but
only after manual pw-link wiring). It is now the blocker again on the current
NixOS deployment.

**Creating links is GraphManager's primary job.** The owner has elevated this
from a known background issue to Critical: a system that requires manual wiring
on every boot is unacceptable for a production audio workstation that must
auto-start.

### Distinction from F-272

F-272 covers **sleep-based polling during mode switches** — the reconciler
eventually creates links, but callers can't deterministically wait for it.
US-140 (PR #27) addresses F-272 with epoch-based settlement.

F-292 is a different problem: **the reconciler never creates the links at all
on startup.** This is not a timing/race issue — it's a functional failure of
the reconciler's core link-creation logic when transitioning from no-mode to
the initial mode.

### Root Cause (confirmed)

`90-no-auto-link.conf` with `policy.standard = disabled` was disabling ALL
WirePlumber format negotiation — not just linking. This prevented WP from
activating ALSA adapter nodes (`SPA_PARAM_PortConfig`, format negotiation),
leaving nodes in `suspended` state with zero ports. Without ports, the GM
reconciler had nothing to link.

This is the same class of failure as GM-12 Finding 2 ("ALL PipeWire nodes
went to suspended state with 0 ports") but caused by an overly broad WP
config override rather than WP being fully masked.

The GM reconciler itself is not at fault — it correctly identifies missing
links but cannot create them because the target ports do not exist.

### Impact

- **Boot-to-audio is broken.** The system cannot auto-start into a working
  audio state without manual intervention.
- **Every operational use requires SSH + pw-link.** This defeats the purpose
  of the web UI and automated mode management.
- **Blocks US-062 (boot-to-DJ mode)** which was previously marked complete
  but depends on GM creating links automatically.

### Fix (D-065)

Two changes, both applied on Pi via nixos-rebuild (runtime fix confirmed):

1. **Remove `90-no-auto-link.conf`** from the flake's WP configPackages.
   This restores WP format negotiation and node activation while the
   remaining two anti-bypass layers (`node.autoconnect = false` +
   GM reconciler cleanup) prevent unwanted auto-linking.

2. **Add `node.always-process = true`** to the PipeWire filter-chain
   convolver configuration. This prevents the convolver from entering
   suspended state during mode transitions.

The permanent fix requires a PR to update the flake. The runtime fix
(file removal + nixos-rebuild) has been applied on the Pi.
