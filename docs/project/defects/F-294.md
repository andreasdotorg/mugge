## F-294: local-demo.sh still contains `policy.standard = disabled` — F-292 class issue

**Severity:** Medium
**Status:** open
**Found in:** `scripts/local-demo.sh` (line 208)
**Affects:** local-demo stack, E2E tests
**Found by:** team-lead (session 15, during F-292 deployment)

### Description

`scripts/local-demo.sh` line 208 contains `policy.standard = disabled` in its
WirePlumber configuration. This is the same overly broad WP policy override that
caused F-292 (GM fails to create links on startup) in the production NixOS image.

D-065 removed `90-no-auto-link.conf` from the production flake and documented
the two-layer anti-bypass architecture (node.autoconnect=false + GM reconciler
cleanup). The local-demo stack still uses the old three-layer approach with
`policy.standard = disabled`, which prevents WP from activating nodes and
negotiating formats in local-demo.

### Impact

- local-demo WP nodes may remain in suspended state with zero ports (same
  failure mode as F-292)
- E2E tests running against local-demo may not accurately represent production
  behavior
- The local-demo stack diverges from the production D-065 architecture

### Fix required

1. Remove `policy.standard = disabled` from `scripts/local-demo.sh` line 208
2. Ensure local-demo uses the same two-layer anti-bypass approach as production
   (node.autoconnect=false + GM reconciler cleanup)
3. Verify local-demo E2E tests still pass after the change

- D-065 (two-layer anti-bypass architecture)
- D-043 (original three-layer architecture — amended by D-065)
