## F-295: Audible clicks during Mixxx DJ playback on NixOS

**Severity:** High
**Status:** root-cause-identified (fix testing in progress)
**Found in:** xHCI USB IRQ contention on CPU 0 — graph cycle budget pressure
**Affects:** DJ mode audio quality — all DJ playback
**Found by:** owner (session 15, during DJ load test after F-291 RT fix)

### Description

Audible clicks during normal Mixxx DJ playback on the NixOS deployment. The
clicks are continuous during playback — not related to PipeWire restart, mode
switching, or startup transients. This is a distinct issue from F-187 (noise
on channels after multiple PW restarts) and F-016 (glitches after PW restart
with capture adapter).

### Evidence

- 43-minute DJ load test (session 15, post F-291 RT fix)
- pw-top shows +107 Mixxx errors accumulated over the 43-minute session
- PipeWire convolver pipeline itself is clean (~0.07 xruns/min, likely
  startup transients only)
- The errors are concentrated in the Mixxx JACK client, not in the
  PipeWire filter-chain or other audio services

### Root Cause (confirmed)

**xHCI USB IRQ cache pollution on CPU 0** competing with PipeWire audio
threads for graph cycle budget. The USBStreamer's xHCI host controller has
accumulated 100M+ interrupts, all pinned to CPU 0. This IRQ load causes
L1/L2 cache eviction and scheduling jitter on CPU 0, where audio threads
also run. Under tight graph cycle budgets (lower quantum), the jitter
exceeds the cycle deadline and produces buffer errors in the Mixxx JACK
client.

**Evidence — quantum scaling confirms cycle budget pressure:**
- q512: 4.6 ERR/min (tightest budget, most errors)
- q1024: 2.7 ERR/min baseline (confirmed by worker-2 final monitoring; earlier
  0.4/min reading was statistical anomaly)
- q2048: 0.8 ERR/min (most headroom, fewest errors)

**Disproven hypothesis:** Initial investigation suspected the dormant
`ada8200-in` capture adapter node (`node.driver=true`) was the cause.
Destroying the node appeared to stop errors, but this was statistical
variance — subsequent testing confirmed no effect on ERR rate. The
ada8200-in node is not the root cause.

### Fix Options

1. **Primary: IRQ affinity pinning.** Pin xHCI USB IRQ to CPU 2-3,
   away from audio threads on CPU 0-1. This eliminates cache pollution
   from the IRQ handler competing with audio processing. Testing in
   progress.

2. **Fallback: q2048.** Increase PipeWire quantum from 1024 to 2048.
   This gives 4x the cycle budget headroom, reducing ERR rate to
   ~0.8/min. Trade-off: latency increases from ~21ms to ~43ms (still
   acceptable for DJ/PA mode, but further from live mode target).

### Key Observations

- F-291 RT fix (SCHED_FIFO/88 for PipeWire) resolved convolver pipeline
  xruns but did NOT resolve the Mixxx clicks — different root cause
- Error rate scales inversely with quantum size, confirming cycle budget
  pressure rather than a software bug
- xHCI IRQ count (100M+) indicates sustained high-rate USB traffic from
  the USBStreamer's 8-in/8-out ADAT stream

### Distinction from Other Defects

- **F-187** (Critical): Noise on ALL 4 channels + broken spectrum after
  multiple PW restarts. Different symptom — F-187 is catastrophic noise,
  F-295 is intermittent clicks during normal operation.
- **F-016** (Medium): Glitches specifically after PW restart with capture
  adapter. F-295 occurs during continuous playback, not post-restart.
- **F-291** (RESOLVED): PW at SCHED_OTHER. Fixed — PW now at FIFO/88.
  F-295 persists after F-291 fix, confirming a different root cause.
