## US-156: Static Route Persistence in NixOS Configuration

**As** the system operator,
**I want** the Pi's static network route to the local network gateway to be
declared in the NixOS configuration,
**so that** network connectivity survives reboots without manual `ip route`
commands.

**Status:** ready
**Priority:** High (NixOS stabilization)
**Effort:** < 0.5 worker days (single NixOS networking config line)
**Origin:** Session 15 deployment — route lost on reboot
**Depends on:** US-072 (NixOS build — deployed)
**Blocks:** none
**Cross-references:** none

### Background

The Pi's default route is currently set manually or via DHCP. When the network
configuration changes (e.g., static IP assignment in NixOS), the default gateway
must be declared in the NixOS configuration to persist across reboots. Without
this, the Pi loses internet/LAN connectivity after every reboot until a manual
`ip route add` is run.

### Acceptance Criteria

- [ ] AC #1: **NixOS networking config declares static route.** The flake's
      NixOS configuration includes `networking.defaultGateway` (or equivalent
      `networking.interfaces.<iface>.ipv4.routes`) pointing to the correct
      gateway for the deployment network.
- [ ] AC #2: **Route survives reboot.** After `nixos-rebuild switch` and a
      clean reboot, `ip route show` shows the correct default route without
      manual intervention.
- [ ] AC #3: **Pi reachable from dev machine.** SSH to the Pi works after
      a cold boot with no manual network setup.

### Definition of Done

- [ ] All acceptance criteria met
- [ ] Deployed and verified on Pi (reboot test)
