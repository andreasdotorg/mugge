## US-158: GraphManager Manages ada8200-in Capture Adapter Lifecycle Per Mode

**As** the DJ/operator,
**I want** the GraphManager to manage the ada8200-in capture adapter node
lifecycle per mode (destroy in DJ, create in live),
**so that** only mode-relevant nodes are present in the PipeWire graph,
reducing unnecessary driver scheduling overhead and preparing the system
for live mode capture requirements.

**Status:** ready
**Priority:** Medium (graph hygiene improvement — NOT the F-295 fix)
**Effort:** ~1 worker day
**Origin:** F-295 investigation (session 15) — AE recommended as graph hygiene
**Depends on:** US-059 (GraphManager core — deployed)
**Blocks:** none
**Cross-references:** D-043 (GM sole link manager), US-062 (boot-to-DJ mode)

### Background

During F-295 investigation, the `ada8200-in` capture adapter node (ADA8200
ADAT input side, used for vocal mic in live mode) was identified as an
unnecessary node in the PipeWire graph during DJ mode. The node has
`node.driver = true`, so PipeWire includes it in the scheduling cycle even
when no clients consume its capture streams.

**Note:** F-295 root cause was ultimately identified as USB isochronous
transfer jitter on the VL805 xHCI controller combined with tight ALSA
buffer margin (448 samples at period-num=4) — NOT the ada8200-in node.
Removing ada8200-in does not fix F-295. However, managing mode-dependent
node lifecycle is still a valid graph hygiene improvement — only nodes
needed for the current mode should be present.

### Design

The GraphManager already manages link topology per mode. This extends that to
node lifecycle:

- **DJ mode:** GM destroys (or suspends) the `ada8200-in` node. No capture
  input is needed. The output-side `ada8200-out` node remains active for
  speaker output.
- **Live mode:** GM creates (or resumes) the `ada8200-in` node. Vocal mic
  input routes through the capture adapter to the convolver/IEM path.
- **Standby mode:** Capture adapter state TBD (destroy is safest default).

Implementation options:
1. `pw-cli destroy` / `pw-cli create-node` (simple, uses existing tooling)
2. `pw-cli set-param` to toggle `node.pause` (if PipeWire supports it)
3. GM Rust code manages node via libpipewire API (cleanest but more work)

### Acceptance Criteria

- [ ] AC #1: **DJ mode: no ada8200-in node.** When GM enters DJ mode, the
      `ada8200-in` capture adapter node is not present in the PipeWire graph.
      Verified by `pw-cli list-objects | grep ada8200-in` returning empty.
- [ ] AC #2: **Live mode: ada8200-in node present.** When GM enters live mode,
      the `ada8200-in` capture adapter node is present and active with ports
      available for linking.
- [ ] AC #3: **Fewer graph nodes in DJ mode.** pw-top shows no ada8200-in
      driver node during DJ playback, reducing graph scheduling overhead.
- [ ] AC #4: **Mode transition preserves audio.** Switching from DJ to live (or
      vice versa) does not produce transients, dropouts, or require PipeWire
      restart. The ada8200-out node remains active throughout.
- [ ] AC #5: **Boot-to-DJ clean.** On cold boot into DJ mode, the system starts
      without the capture adapter node. No manual intervention needed.

### Definition of Done

- [ ] All acceptance criteria met
- [ ] AE consultation: confirm capture adapter removal does not affect output
      path or introduce USBStreamer enumeration issues
- [ ] Deployed and verified on Pi (DJ load test, mode switch test)

### Note

This story is a graph hygiene improvement, not a fix for F-295 (Mixxx clicks).
F-295 root cause is USB isochronous transfer jitter on the VL805 xHCI
controller + tight ALSA buffer margin — fixed by period-num 4→5, not by
ada8200-in removal.
