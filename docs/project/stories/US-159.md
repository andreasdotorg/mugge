# US-159: pw-top metrics in Web UI system tab

**Status:** BACKLOG
**Priority:** Low
**Sprint:** Not selected

## User Story

As an audio engineer operating the Pi workstation, I want to see real-time
PipeWire graph performance metrics in the web UI system tab, so that I can
troubleshoot RT scheduling and xrun issues without SSHing to the Pi.

## Context

Diagnosing RT audio issues (F-291, F-295, F-296) currently requires SSH
access and manual `pw-top` invocation. The web UI already has a system tab
but lacks audio graph telemetry. Surfacing pw-top data would make RT
troubleshooting accessible during live operation.

## Data source

`pw-top -b` (batch mode) outputs machine-parseable per-node metrics once
per second. Key fields:

| Field | Use |
|-------|-----|
| ERR (cumulative) | Missed deadline count — headline "is audio dropping?" metric |
| B/Q ratio | Processing headroom — under 50% comfortable, over 80% danger |
| Wait | USB jitter / scheduling delay indicator |
| Quantum | Confirms active mode (256=live, 1024=DJ) |
| Rate | Sample rate confirmation |
| Node status | Which nodes are running vs idle |

## Acceptance Criteria

1. Web UI system tab displays per-node: name, quantum, rate, B/Q%, ERR count
2. ERR count shows both cumulative and rate (ERR/min over trailing window)
3. Data updates at least once per second
4. Visual indicator when B/Q exceeds 50% (warning) or 80% (danger)
5. No additional CPU overhead >0.5% on Pi 4 at quantum 1024

## Implementation Notes

- Consider polling `pw-top -b -n 1` or using PipeWire's profiler module
  (`libpipewire-module-profiler`) for lower-overhead access
- pcm-bridge already has a websocket path to the web UI — could extend it,
  or add a separate lightweight poller
- The profiler module provides the same data pw-top uses, accessible via
  PipeWire's native protocol without spawning a subprocess

## Dependencies

- Web UI (US-110) must be deployed
- No blocking dependencies — can be developed independently
