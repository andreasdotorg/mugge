### Background

F-295 investigation identified two contributing factors to Mixxx clicks:
1. **F-296 (primary):** Mixxx JACK client threads running at SCHED_OTHER
   instead of SCHED_FIFO. PipeWire's JACK bridge promotes client threads to
   RT via `mod.rt`, but NNP blocks `sched_setscheduler`. Fix: set
   CPUSchedulingPolicy=fifo/70 on the Mixxx systemd service (same pattern
   as PipeWire's FIFO/88 fix for F-291).
2. **USB isochronous jitter:** VL805 xHCI ~1ms jitter on USBStreamer transfers.
   Mitigated by period-num=5 (F-295 fix deployed).

Commit `87e4ab96` implements the FIFO/70 fix. This story covers deployment,
verification, and assessment of the combined fix effectiveness.

### Acceptance Criteria

- [ ] AC #1: **FIFO/70 deployed.** Mixxx systemd user service has
      `CPUSchedulingPolicy=fifo` and `CPUSchedulingPriority=70` in the NixOS
      configuration. Deployed via `nixos-rebuild switch`.
- [ ] AC #2: **Thread scheduling verified.** After Mixxx launch, `chrt -p`
      confirms Mixxx main thread and JACK audio threads are running at

- [ ] AC #4: **Audibility assessment.** Owner listens to DJ playback through
      the full signal chain (headphones or monitors at safe level) and confirms
      whether remaining ERR (if any) are audible. Document the assessment.
- [ ] AC #5: **Escalation path documented.** If FIFO/70 is insufficient:
      document remaining ERR rate, investigate PW 1.6.2 JACK bridge changes,
      and assess q2048 fallback trade-off.
