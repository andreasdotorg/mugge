## US-162: Reaper Auto-Launch as NixOS Systemd User Service

**As** the live vocalist/operator,
**I want** Reaper to launch automatically when the Pi boots into live mode,
**so that** the live performance DAW is ready without manual intervention.

**Status:** done (Reaper service created, commit `5eccdaf5`, session 16)
**Priority:** High (gig-blocking, must-have)
**Effort:** ~0.5 worker days
**Origin:** Session 16 gig sprint — live mode parity
**Depends on:** US-072 (NixOS build — deployed), US-157 (Mixxx service — pattern)
**Blocks:** US-166 (live mode E2E verification)
**Cross-references:** US-157 (Mixxx service — same pattern), D-063 (audio gate),
US-062 (boot-to-DJ — pre-NixOS)

### Background

Same pattern as US-157 (Mixxx auto-launch), but for Reaper in live mode.
Reaper is the DAW for live vocal performance (Cole Porter repertoire with
backing tracks). It needs to be launched via `pw-jack reaper` with RT
scheduling (FIFO/70, same as Mixxx per D-066).

The service follows the US-157 pattern:
- NixOS systemd user service
- `pw-jack reaper` wrapper
- CPUSchedulingPolicy=fifo, priority 70
- Started by labwc autostart (needs Wayland display)
- ExecStartPre readiness probe via `pw-cli info`

### Design Differences from Mixxx (US-157)

1. **Mode-conditional:** Reaper should only launch in live mode, not DJ mode.
   If always-launch is chosen (per US-157 design), Reaper and Mixxx would
   both be running — investigate whether this is acceptable on Pi 4 resources.
2. **Project auto-load:** Reaper should ideally load the live performance
   project file automatically. This may require a command-line argument
   (`reaper <project-file>`).
3. **IEM routing:** Reaper outputs to ch 7-8 (singer IEM) via direct PW link
   bypassing the convolver. GM establishes this routing in live mode.
