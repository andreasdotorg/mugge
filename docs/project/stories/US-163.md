## US-163: ADA8200 Capture Adapter Re-enablement with node.passive Fix

**As** the live vocalist,
**I want** the ADA8200 capture adapter (ada8200-in) re-enabled in the PipeWire
graph with the correct `node.passive=true` setting,
**so that** vocal mic input (ch 1-2) is available for live mode performance.

**Status:** selected
**Priority:** High (gig-blocking, must-have)
**Effort:** < 0.5 worker days
**Origin:** Session 16 gig sprint — live mode prerequisite
**Depends on:** US-072 (NixOS build — deployed), D-065 (WP format negotiation restored)
**Blocks:** US-166 (live mode E2E verification)
**Cross-references:** US-158 (GM lifecycle management per mode — separate,
medium priority), F-295 (capture adapter was removed during investigation),
pcm-bridge node.passive bug (session 16 fix)

### Background

During F-295 investigation, the `20-usbstreamer.conf` capture adapter
configuration was removed as a debugging step. The capture adapter (`ada8200-in`)
provides the ADA8200's ADAT input channels — specifically ch 1-2 for vocal mic
input in live mode.

The pcm-bridge `node.passive` bug discovered in session 16 showed that missing
`node.passive = true` on capture nodes causes them to self-promote to driver
status, increasing ERR count. The re-enabled capture adapter must include this
fix.

**This story is the immediate re-enablement for gig readiness.** US-158 (GM
manages ada8200-in lifecycle per mode) is a separate, more sophisticated story
that adds mode-conditional destroy/create — that can follow later.

### Acceptance Criteria

- [ ] AC #1: **20-usbstreamer.conf restored.** The capture adapter configuration
      file is re-added to the NixOS PipeWire config with `node.passive = true`
      on the capture node. Deployed via `nixos-rebuild switch`.
- [ ] AC #2: **Capture adapter active.** After deployment, `pw-cli list-objects`
      shows the `ada8200-in` node with ports available for linking.
- [ ] AC #3: **node.passive confirmed.** The capture adapter node does NOT
      self-promote to driver. Verified by `pw-top` — ada8200-in should show
      as a follower node, not a driver.
- [ ] AC #4: **No ERR regression.** DJ playback ERR rate does not increase
      with the capture adapter present (compared to baseline without it).
      Measured via `pw-top -b -n 60` during Mixxx playback.
- [ ] AC #5: **Mic input routable.** In live mode, GM can create links from
      ada8200-in capture ports to the convolver/IEM path. Verified by
      `pw-link` or GM RPC.

### Definition of Done

- [ ] All acceptance criteria met
- [ ] AE consultation: confirm node.passive=true is correct for capture adapter
- [ ] Verified on NixOS Pi (DJ ERR regression test + live mode routing test)
