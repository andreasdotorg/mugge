## US-165: DJ-Live Mode Switching Verification on NixOS Pi

**As** the operator,
**I want** to verify that switching between DJ and live modes works correctly
on the NixOS Pi,
**so that** I can transition between DJ sets and live vocal performances at
the gig without restarting the system.

**Status:** selected
**Priority:** High (gig-blocking, must-have)
**Effort:** ~0.5 worker days (Pi hardware session required)
**Origin:** Session 16 gig sprint — mode switching never tested on NixOS
**Depends on:** US-161 (Mixxx xrun fix), US-164 (live mode E2E), US-072 (NixOS)
**Blocks:** none
**Cross-references:** D-043 (GM sole link manager), D-063 (audio gate),
D-042 (quantum settings), US-059 (GraphManager core)

### Background

GraphManager mode switching has been tested on the pre-NixOS system and in
local-demo, but never on the NixOS Pi deployment. The transition involves:

- **DJ -> Live:** GM changes link topology (Mixxx -> Reaper routing), quantum
  changes from 1024 to 256, capture adapter becomes relevant.
- **Live -> DJ:** GM changes link topology back, quantum changes from 256 to
  1024, capture adapter becomes irrelevant.

Key concerns for NixOS:
1. Does quantum change work via `pw-metadata` on the NixOS deployment?
2. Does GM correctly tear down old links and create new ones?
3. Are there transients or audio gaps during the transition?
4. Does the audio gate behave correctly during mode switch?

### Acceptance Criteria

- [ ] AC #1: **DJ -> Live transition.** Trigger GM mode switch from DJ to
      live. Verify: link topology changes, quantum changes to 256, Reaper
      routing established, IEM path active. No PipeWire restart required.
- [ ] AC #2: **Live -> DJ transition.** Trigger GM mode switch from live to
      DJ. Verify: link topology changes, quantum changes to 1024, Mixxx
      routing re-established. No PipeWire restart required.
- [ ] AC #3: **No transients.** Neither transition produces audible transients,
      pops, or clicks through the amplifier chain. Verified by monitoring
      output during transition (at safe volume).
- [ ] AC #4: **Audio gate behavior.** The audio gate remains in its current
      state during mode switch (does not close and re-open unexpectedly).
      Or if it does close: document the behavior and assess whether it is
      acceptable for live use.
- [ ] AC #5: **Round-trip stable.** Perform DJ -> Live -> DJ cycle at least
      3 times. Audio remains clean after each transition. No accumulated
      errors or leaked links.

### Definition of Done

- [ ] All acceptance criteria met
- [ ] Test performed on NixOS Pi with physical audio hardware
- [ ] AE consultation: review transition safety (transients, gate behavior)
- [ ] Lab note documenting mode switch behavior and any issues found
