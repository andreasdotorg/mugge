## US-167: Pre-Flight Checklist for Gig Setup

**As** the operator setting up at a venue,
**I want** a documented pre-flight checklist for gig startup,
**so that** I can follow a repeatable sequence to verify the audio system is
ready before the performance begins.

**Status:** selected
**Priority:** Medium (should-have)
**Effort:** ~0.5 worker days (documentation)
**Origin:** Session 16 gig sprint — operational readiness
**Depends on:** US-161 (xrun fix), US-164 (live mode verified), US-165 (mode
switching verified)
**Blocks:** none
**Cross-references:** docs/operations/safety.md (existing safety doc),
SETUP-MANUAL.md, D-063 (audio gate)

### Background

The system needs a documented gig startup sequence that an operator can follow.
This is a documentation deliverable, not a code change. It should cover the
complete power-on to ready-to-perform workflow for both DJ and live modes.

The existing `docs/operations/safety.md` covers safety constraints but not the
full operational startup sequence. `SETUP-MANUAL.md` covers system installation
but not gig-day operation.

### Acceptance Criteria

- [ ] AC #1: **DJ mode pre-flight checklist.** Step-by-step checklist:
      1. Power on Pi
      2. Verify audio stack auto-starts (PipeWire, GM, filter-chain)
      3. Verify Mixxx auto-launches
      4. Verify Hercules controller detected
      5. Verify DJ routing established (pw-link or GM status)
      6. Open audio gate (verify safe gain levels)
      7. Sound check: play test track, verify all outputs
      8. Ready to perform

- [ ] AC #2: **Live mode pre-flight checklist.** Step-by-step checklist:
      1. Power on Pi (or switch from DJ mode)
      2. Verify Reaper auto-launches
      3. Verify mic input (ch 1-2) active
      4. Verify IEM output (ch 7-8) active
      5. Verify quantum 256 active
      6. Open audio gate
      7. Sound check: mic test, IEM test, monitor test
      8. Ready to perform

- [ ] AC #3: **Troubleshooting quick reference.** Common issues and fixes:
      no audio output, controller not detected, high ERR rate, mode switch
      failure. One-line diagnosis + fix for each.

- [ ] AC #4: **Placed in docs/operations/.** Document lives alongside the
      existing safety.md as `docs/operations/pre-flight.md`.

### Definition of Done

- [ ] All acceptance criteria met
- [ ] TW review: document is clear, actionable, and follows project doc style
- [ ] AE consultation: verify safety steps in checklist match safety.md
- [ ] Owner review: checklist matches actual gig workflow expectations
